---
name: helix-ml
description: Run and compare local ML and reinforcement learning experiments through Helix MCP. Use when the user asks to use Helix or run a Helix experiment on their own computer.
---

Use the current agent session to write candidates and call Helix. Do not launch another Codex/Claude process or ask for an API key.

Read `helix_info` for the runtime and metric catalog. Infer a proposed task and metric from the user's message, but show the target/exclusions, model restriction, optimization rule, validation/test split and time/trial budgets before training. Ask only for missing choices that affect correctness; an explicit user specification already authorizes those choices. For joint objectives, Helix supports same-direction supervised metrics ranked by their equal-weight mean; disclose this and preserve all requested metrics. Do not invent a metric or drop one silently.

Read the verified compute capabilities from `helix_info`. Default to `device="auto"`; honor explicit CPU/CUDA/MPS requests. Show the proposed device before training. For each `helix_run_trial`, set `device` to the device the code actually uses. Use `cpu` for scikit-learn and other CPU-only algorithms, even if a GPU is available. Use CUDA for compatible PyTorch/XGBoost models and MPS for compatible PyTorch models on Apple Silicon. Availability is verified with a small forward/backward pass, not a promise that every model supports the device. Do not claim CPU-only models use the GPU.

Follow the contract's device handling in both training and reload code. Avoid float64 on MPS; move models and tensors together. Preserve the installed PyTorch wheel instead of downloading another variant. Package/version or out-of-memory errors must be reported and repaired explicitly; never silently change an explicit GPU request to CPU. CPU candidates remain valid in auto experiments. GPU memory estimates are not enforced quotas. Save portable CPU state dictionaries when exporting PyTorch models.

For cuML, use direct `cuml` estimators on CUDA with an exact `cuml-cu12` or `cuml-cu13` dependency matching the runtime. Linux/WSL2 with NVIDIA is required; native Windows and macOS are unsupported. Use float32 CuPy arrays, convert predictions to host arrays for JSON, and preserve preprocessing in exports. Prefer models with out-of-sample predict/transform; do not fit on validation rows or label a CPU fallback as GPU training. KMeans and fixed-dimension PCA fixtures are available under `mcp/fixtures/cuml` in the installed app. Cumulative-variance PCA currently retains the existing sklearn reference protocol.

For TensorFlow/Keras choose CPU with `tensorflow`, or Linux/WSL2 CUDA with `tensorflow[and-cuda]`. TensorFlow does not use PyTorch MPS. Verify TensorFlow's own GPU devices and actual tensor placement; PyTorch's successful probe does not verify TensorFlow. Disable silent device fallback and use GPU memory growth. Start Keras with `jit_compile=False`; XLA needs its own compatible compiler/toolchain and is not verified by the device probe. Native `.keras` and SavedModel exports must pass both the format loader and fresh-process prediction check. Custom objects and conversions are model-specific, not guaranteed by framework availability.

For reinforcement learning, read the supported standard Gymnasium environments from `helix_info`. Use `helix_create_rl_experiment` instead of a CSV experiment; show the environment, episode horizon, evaluation episode count and budgets first. `helix_run_rl_trial` trains a fresh SB3 policy with the chosen algorithm, timesteps and optional hyperparameters. Use PPO/A2C for either action type, DQN for discrete actions, and SAC/TD3/DDPG for continuous actions. Prefer CPU for small MLP policies. Packages install automatically. Poll status; compare measured mean episode returns on fixed validation seeds. Status details include actual training timesteps and episode reward history. `helix_finalize` evaluates the selected saved checkpoint once on reserved test seeds, without retraining, then exports the policy and reproduction script. Results describe one training seed; do not present them as evidence across independently trained agents. Custom environments, reward wrappers and Atari preprocessing are not implemented. The CSV instructions below apply only to CSV experiments.

Use an absolute local CSV path with `helix_create_experiment`. Wait for preparation using `helix_status`, then request `details=true` once for the schema, installed packages, class order and full training-code contract. Use compact status for subsequent progress polls; request details again when you need every recorded trial. Clustering needs no target except for external label-based evaluation. Reduction supports a fixed dimension count or a PCA cumulative-variance target. Preserve categorical/text columns when meaningful; exclude identifiers and unintended labels explicitly.

Write a separate source-only directory outside Helix's private state directory. Follow the returned contract for `train.py`, `predict.py`, `plan.json` and any helper modules. Inspect the code for leakage, correct class order, model/strategy restrictions and reload behavior before submitting. Use the installed dependencies; provide exact additional package versions in `helix_run_trial` only when needed. Source files are snapshotted per trial. Extra packages do not carry into later trials automatically: repeat their requested versions for each candidate that needs them.

`helix_run_trial` starts a background job. Poll `helix_status` every few seconds; do other useful work between polls. Use only its measured validation results to compare and improve candidates. Report failures and repair code within the user's remaining budget. `helix_cancel` stops an active job. Extend a budget only when the user requests further work. Keep enough time for final refitting/export; a time limit includes the agent's elapsed planning and editing time.

Call `helix_finalize` once after selecting from validation results. The harness refits the best candidate, checks a fresh-process model reload and evaluates the reserved test set once. Once selection is frozen, no more trials are permitted in that experiment. Report actual metrics and the returned solution ZIP path; show training curves or projections only if measured outputs exist. Never treat a test result as feedback for tuning the same study.

Native execution has normal user permissions, not OS isolation. Run code only within the user's authorized local experiment. Do not read raw held-out labels, Helix's internal evaluation files, other candidates' fit data or unrelated user files. Do not send raw dataset rows to an external service without authorization. The normal CLI inputs omit validation targets, and the evaluator computes scores in its own process; these controls are not protection against hostile Python code. Closing the MCP session interrupts active work while preserving completed trial results.
